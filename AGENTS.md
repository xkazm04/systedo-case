# Adamant (systedo-case) — agent guide

Adtech marketing-automation suite ("Adamant", ex-Systedo). Czech-first (cs is the
source locale, en derived). Public site at `/`, authed product at `/app` with
per-project tenancy. Deploys to Vercel serverless.

**This file is canonical.** `CLAUDE.md` is a shim (an `@AGENTS.md` import plus a generated
context map) and `CONTRIBUTING.md` says the same things to a human. Where two disagree,
this file wins. Declared in `.ai/manifest.yaml` under `guidance.canonical` and enforced by
`npm run agents:surface` (blocking, inside `check:ci`).

**Read before you write:** `.github/agent-review-rubric.md` (the review applied to your
diff — its mechanical half blocks) and `.github/required-checks.json` (what must be green
before a change lands). [`docs/task-index.md`](docs/task-index.md) answers "which document
is this task's document?" — the ADR, runbook, contract or record that governs it — and
[`docs/agent-index.md`](docs/agent-index.md) does the same for the subagent specs in
`.claude/agents/`. Both are held true by tests.

**And that list has a size, so it has a ceiling.** `.github/guidance-budget.json` names the
documents read before the first edit, with a line ceiling on each and on the total
(`npm run guidance:budget`; blocking via `test-unit/guidance-budget.test.mjs`). Everything
else is a LOOKUP reached through `docs/task-index.md` — including
[`docs/agent-guide/conventions.md`](docs/agent-guide/conventions.md), which holds the full
reasoning behind every command and rule below. Moving a document from lookup to read-first
is the expensive decision; raising a ceiling is the paragraph plus the number that pays for it.

## Commands

```bash
npm run dev:local     # DEV_AUTH=true LOCAL_DB=true next dev — fully offline /app
npm run seed:local    # once: dev user + sample projects into .data/systedo.db
npm run dev           # real auth mode (needs Google OAuth + Firestore creds)
npm run check         # typecheck + lint + build
npm run check:fast    # THE INNER LOOP: cheap gates + typecheck + lint + test:fast; not a gate
npm run typecheck:strict # the two flags `strict: true` does not turn on — an instrument, not a gate
npm run test:unit     # node:test suites in test-unit/ — THE GATE
npm run test:fast     # the suites that name a changed file + the always tier; not a gate
npm run test:e2e      # Playwright — also CI's required key-free `e2e-smoke` job
npm run check:ci      # what CI runs, cheapest first; then test:unit, then check
npm run check:ci:timed # the same chain with a clock per stage — what CI actually runs
npm run gates         # the chain with the EXACT NEXT COMMAND for each gate
npm run checkpoint    # open checkpoints an interrupted run left — READ THIS FIRST
npm run lint:fences   # do the three seam fences still FIRE? (blocking via a test)
npm run sast          # repo security rules over src/ — blocking
npm run actions:check # workflow token scope, action pinning, no ${{ }} in a run: script
npm run merge-gate    # the required checks still exist, run on PRs, and can fail
npm run contract:ledger # every rule, what enforces it, what it absorbs, its pin
npm run review:agent  # rubric review of a diff (--base <ref>)
npm run commit:check  # commit-subject rules: --range <range> | --message "<subject>"
npm run docs:parity   # bilingual doc pairs still state their shared facts (blocking)
npm run adr:owner     # which decision governs this file (the reverse of task-index)
npm run context:decay # cross-group imports the context map does not declare
npm run context:conventions -- --path <file>  # local rules for the context you are in
npm run llm:gate      # LLM proof gate (llm:list shows call sites)
npm run llm:budget    # input-side cost of each LLM operation vs its ceiling
npm run llm:models    # which model every LLM record was accepted against
npm run env:manifest  # what runs where past the merge; :check diffs it against the tree
npm run doctor        # env preflight (not a gate)
npm run i18n:audit    # coverage / leftover-source / register audit (ratcheted)
npm run i18n:gate     # localization-wave gate: diffs the tree vs a ref (--base)
```

Reporting instruments and drills (`gates:timings`, `gates:failures`,
`fences`, `revert:drill`, `mutation:drill`, `flake:drill`, `interrupt:drill`,
`harness:drill`, `context:coverage`, `docs:staleness`, `llm:drift`, `llm:candidate`,
`protection:verify`, `issue:dispatch`) are described in
[`docs/agent-guide/conventions.md`](docs/agent-guide/conventions.md). `llm:drift` and
`llm:candidate` spend money: amber, never in `check:ci`.

Gates come in two rungs — blocking (passes today, so red is a regression) and
reporting-with-a-ratchet (prints, fails only when a count rises); see
[ADR-0007](docs/adr/0007-gate-rung-discipline.md). The decision records are in
[`docs/adr/`](docs/adr/README.md) — read the one for a seam before you change it.
**And every gate tells you what to do next.** Each check prints its entry from
[`scripts/gate-remedy.mjs`](scripts/gate-remedy.mjs) when it goes red: the command that
regenerates the artefact, and the file where an exception is recorded.

## Architecture in 10 lines

1. Next.js 16 App Router + React 19; pages `src/app/`, components `src/components/`, logic `src/lib/`.
2. Auth.js v5 (Google) + firebase-admin; prod sessions/data live in Firestore.
3. Dual-store pattern: prod = Firestore; local dev = node:sqlite under `.data/` (`LOCAL_DB=true`). Same store interfaces, env-switched; `DEV_AUTH`/`LOCAL_DB` are ignored when `NODE_ENV=production`.
4. Tenancy: the tenant key embeds userId (`u_{userId}_proj_{projectId}`) — no cross-user IDOR by construction.
5. Every LLM text call goes through ONE chokepoint: `generateStructured()` in `src/lib/llm/index.ts` (dev = Claude CLI on subscription, prod = Gemini flash; no provider → demo mode).
6. Non-chokepoint AI: Leonardo image gen + Gemini vision scoring + embeddings (Creative Studio, patterns RAG).
7. Billing/abuse rails are server-enforced: `usage.consume()` Firestore txn, durable per-IP limits + global daily spend ceiling (`src/lib/ai/durable-limit.ts`) on all paid routes.
8. i18n is colocated: each component owns `const T = { cs: {...}, en: {...} }` (`TDict`), consumed via `useT(T)` (client) / `await getT(T)` (server); central dict only for nav/footer chrome. Contract: `docs/i18n/contract.md`.
9. Six crons in `vercel.json` → `/api/cron/*`, guarded by `CRON_SECRET` through `src/lib/cron-auth.ts` (constant-time).
10. Design system: token-driven (`ink`/`muted`/`surface`/`brand-*`, dark mode via token overrides), shared `Button` in `src/components/ui.tsx`; conventions in `docs/design-system.md`.

## Conventions that bite

Each rule below is the part a run needs before its first edit. Why each gate exists, what
it caught, what it cannot see and how its pins move is in
[`docs/agent-guide/conventions.md`](docs/agent-guide/conventions.md) — open it before you
argue with a gate.

- **Commit on the current branch; never push.** `git push` is denied to Claude Code here;
  every other agent is bound by this line, and the owner pushes after reading the log.
  Without it an unattended harness pushes by default (measured 2026-09-08). The gate bypass
  is denied at the permission layer (`--no-verify`, force-push, `SYSTEDO_SKIP_GATE=1`,
  `HUSKY=0`) - if a gate is red, fix the tree.
- **Pathspec commits only** (shared checkout, concurrent agents):
  `git add <paths>` then `git commit <same paths>`. Never `-A`, never a bare
  `git commit`, never stash or reset work that is not yours.
- **Read the open checkpoints before you start** (`npm run checkpoint`) and pick one up
  rather than re-deriving it. Open one for anything longer than a couple of steps and
  update `--next` *before* the step you might not survive:
  `npm run checkpoint -- --start "<task>" --next "<step>" --budget 20`, then `--done`,
  `--close`. Details: `.agent/README.md`.
- **llm-tool tag contract**: every `generateStructured` call site must carry a
  `// llm-tool: <id>` comment with a registered test in the gate registry.
  `scripts/llm-gate.mjs` (pre-commit + CI) fails on an untagged call site, a chokepoint
  violation, or drifted goldens. Prove on demand with `npm run test:llm` /
  `npm run llm:quality` (amber: they spend money).
  **Accepting a golden needs a reason**: `npm run llm:eval:update -- --reason "..."`.
  The baked scorecard has a floor too (`npm run llm:quality:check`).
- **A prompt has a price, and it is recorded.** A new AI operation records what its input
  costs, the same way it records its shape: `npm run llm:budget -- --accept --reason "..."`.
  `llm:budget:check` is blocking inside `check:ci`.
- **The model surface the harness proves against is pinned in** `test-llm/model-pins.json`.
  Moving a model is two commands in one diff: `npm run llm:drift`, then
  `npm run llm:models -- --accept --reason "…"`.
  **The evals prove today's model; this rehearses tomorrow's**: `npm run llm:candidate`
  runs every operation against the successor in `test-llm/model-candidates.json` (amber).
- **Your diff gets reviewed before a human sees it.** Rubric Part A **blocks** (also as
  `npm run review:agent:gate` inside `check:ci`): a component past 200 LOC, an
  `export const dynamic|runtime|revalidate` under `src/app/`, a deleted test, a new runtime
  dependency, a narrating commit subject, and a pin in `.github/contract-ledger.json` moved
  in the LOOSENING direction without re-dating `accepted.on` and rewriting `reason` in the
  same diff (tightening is free). Deleting a test or adding a dependency needs
  `Ack: <why>` in the commit message or PR body. Part B is a model's comment; it never blocks.
- **Components under 200 LOC preferred** — extract sub-components and data hooks instead of
  growing module files. Debt: `docs/roadmap/component-debt.md`.
- **Three of these constraints are lint rules, not just prose.** `eslint.config.mjs`
  fences the LLM chokepoint (no `GoogleGenAI` client or provider adapter outside
  `src/lib/llm/`), the store seam (no `firebase-admin` or `node:sqlite` outside `src/lib/` —
  routes and components go through a store), and route segment config (no
  `export const dynamic|runtime|revalidate|fetchCache|dynamicParams` under `src/app/`). The
  fix is the seam, never an `eslint-disable`. There is deliberately no Prettier or Biome
  (ADR-0008): do not reformat files you are not otherwise changing.
- **And their exception lists have a ceiling.** Every exception list (lint fences,
  `.github/security/sast-allowlist.json`, `.github/flaky-tests.json`) is counted in
  `.github/contract-ledger.json`. **Adding an exception is therefore a two-line diff**: the
  entry, and the ceiling that pays for it. Every pin carries `accepted: { on, reviewBy }`.
  Thresholds and ratchet baselines (`RATCHET.*`, `FLOOR`, `COMPONENT_LOC_LIMIT`) are pinned
  the same way; `contract:ledger:check` fails when a number crosses its pin or has none.
- **Security rules are a gate, not a review note.** `npm run sast` blocks a new route
  under `src/app/api/` that establishes no caller identity, a `"use client"` module reading
  a server env var, a route importing the decrypted BYOM key, SQL built by interpolation,
  and five more. Exceptions only with a written reason in the allowlist; no in-code opt-out.
- **A dependency's provenance is asserted, not assumed.** Packages come from the public
  registry over https with a sha512 integrity hash, and the set of packages that run code
  at install time is a pinned list of six (`test-unit/dependency-lockfile.test.mjs`).
- **What may stop a change is written down.** `.github/required-checks.json` lists the
  checks that must be green, each with its reason; `npm run merge-gate` keeps them real.
  Master ships on push, so `.husky/pre-push` enforces the same list before the push.
- **And the chain is ordered by a clock, not by a claim.** Run `npm run gates:timings`
  before adding a gate and know what the loop already costs.
- **A half of the harness that stops RUNNING has to say so.** A key-gated step declares
  its degradation in `scripts/harness-degradation.mjs`; `harness:degradation:check` refuses
  one that does not.
- **A commit subject names the change, not the session.** Rubric A5 blocks a subject that
  is not a conventional-commit header, runs to a second sentence, or narrates the run.
  If a lane commits for you, the report's first line is the subject — write it as one.
  Check: `npm run commit:check -- --message "<subject>"`. A run with no change owes no commit.
- **And the body says who wrote it, in a form git can count.** An agent's commit carries
  `Co-Authored-By: <who> <email>` (or `Assisted-by:` / `Generated-by:`) below a blank line;
  the `prepare-commit-msg` hook adds `Agent-Harness:` and friends from the environment.
  A lane that commits for itself writes its own trailers (`scripts/issue-dispatch.mjs`).
- **And the third fact is which DECISION the change served**, as a trailer:
  `Decision: ADR-0001` or `Decision: rubric-A6, ADR-0007`. Citing nothing is the common and
  correct case. What is refused is a citation that does not RESOLVE (`.husky/commit-msg`);
  `npm run commit:check -- --decisions` lists what may be cited.
- **The bilingual docs are held in step by a gate, not by care.** `README.md` is the
  source, `docs/README.cs.md` is transcreated; `npm run docs:parity` blocks on drift. Never
  delete a rule to go green.
- **And the API document is held to the routes, not to a reviewer.** The derived half of
  `docs/api/openapi.json` is re-derived with `npm run api:surface:write`, never hand-edited;
  each operation needs one written sentence (not `TODO`).
- i18n parity is the type system: `TDict`/`Messages` make a key added to one locale and not
  the other a `typecheck` failure. There is no parity script — do not invent one.
  `npm run i18n:audit` is reporting with a `RATCHET` baseline in `scripts/i18n-audit.mjs`:
  fix findings and lower it in the same commit; never raise it.
- `context-map.json` maps files to feature contexts; read it at task start and
  scope edits to the relevant context's `file_paths`. It is an index, not an inventory.
- **The map's group boundaries are a constraint on the diff, not just a
  description.** `npm run context:decay:check` (blocking) fails when your change makes a
  file import a feature group it did not import before. Import through a shared context,
  move the file, or declare the crossing in `cross_refs`.
- **Guidance here is repository-wide and the code is not.** Local rules per context live
  in `.github/context-conventions.json`; ask with the path you hold:
  `npm run context:conventions -- --path <file>`.
- **And the suite is measured for the repository, while the work is done in a context.**
  Floors hold on five contexts — the LLM chokepoint, the metering, the campaign store backend, the Sklik write path and the cron spine — may not fall to zero claimed files
  (`.github/context-test-floors.json`): write the test alongside the change there.
- **Coverage says how much code runs; a mutation drill says whether a wrong answer would be caught.**
  A survivor in `npm run mutation:drill` is fixed with the missing assertion, never a
  weaker mutant.
- **A gate that fails at random is not a gate for long.** A flaky test has three honest
  answers, and re-running is not one: fix it, quarantine it in `.github/flaky-tests.json`
  (moving its ceiling in the same diff), or delete it with an `Ack:`.
- **The deploy target is declared, and the declaration is diffed against the tree.**
  A new cron, runtime bump or env var goes into `.github/environments.json` in the same diff
  (`npm run env:manifest:check`). Deploy/env questions: `docs/deploy.md`.
- **A second standard that nothing executes gives no feedback.** `typecheck:strict` is a
  reporting step; once a baseline is accepted, a change that adds strict errors fails it.
- **The tests prove the answer is right; a budget is what notices it got slow.** Five
  routes have ceilings in `.github/perf-budgets.json`, measured in the required E2E job.
  **A perf budget notices a page that got slow; nothing noticed a page that stopped being usable.**
  `.github/a11y-budgets.json` holds six blocking layout invariants (lang, `<main>`, skip
  link, named icon buttons...) in the same job.
- **The checkpoint gate reads what is on disk; nothing ever produced the interruption.**
  `npm run interrupt:drill` rehearses a killed lane against a scratch directory only.
- **What agents got wrong here is written down once, not rediscovered.** Before a run,
  read the rows in [`docs/agent-lessons.md`](docs/agent-lessons.md) whose `standing` is
  `partial` or `unfenced`.

## Which of these rules will actually stop you

Everything above is prose, and prose does not fail. Some of it has a fence behind
it — a lint rule, a gate, a test, a hook — and some of it holds only because the
reader chose to obey it. **Those two read identically in a document, and the
difference is the single most useful thing to know before you start.** So the map
is written down, in [`.github/constraint-map.json`](.github/constraint-map.json),
and summarised here.

It is not a second [contract ledger](.github/contract-ledger.json): that file is
keyed by the ENFORCEMENT — one row per rule a gate, a lint block or a SAST check
defines, with the exception list it is absorbing and the ceiling that pays for it,
answering *what is this fence letting through*. This one is keyed by the RULE as
this document states it, and answers the question you have before you write
anything: *if I get this wrong, will anything notice?* Where a rule is in both,
the map carries the ledger's row id and a test refuses to let them disagree about
whether anything runs.

`rung` is the column that matters: **blocking** — something goes red on the
machine that broke it; **reporting** — it is measured and printed, and fails only
when a count rises ([ADR-0007](docs/adr/0007-gate-rung-discipline.md));
**partial** — some breaches are caught and the map's `gapNote` says which are not;
**honour** — nothing runs, and the `mitigation` field says what (if anything)
would notice afterwards.

lint block `eslint.config.mjs` does not declare, a quote no longer in the file it
is attributed to, a row here with no entry there — and, the property that stops
the map rotting, **a stage added to `check:ci` with no rule attached to it** — all
turn `npm run test:unit` red. Adding a rule to this file therefore means adding
its row; adding a fence means saying which rule it fences.

## What you may do unattended

This repository holds live credentials — Google Ads and Sklik tokens, a Resend
key, a Leonardo key, Gemini and provider keys — and most of its commits are
written by an agent working alone. So the boundary is not "be careful", it is a
list. **Green means do it; amber means do it and say so in the change; red means
stop and ask the operator, every time, even if you did the same thing an hour
ago.**

**Green — go ahead.**

- Read anything in the tree. Run `npm run dev:local`, `seed:local`, `check`,
  `check:ci`, `test:unit`, `test:e2e`, `lint`, `typecheck`, and any of the
  `--check` / audit / gate scripts. All of them are offline and free: with no
  provider configured every AI operation falls back to its deterministic `demo`,
  which is a product property, not a dev convenience.
- Edit code, tests and docs inside the context you were asked to change
  (`context-map.json` says which files that is).
- Commit **by pathspec** — `git add <paths>` then `git commit <same paths>`.
  Never `-A`, never a bare `git commit`, never stash or reset work that is not
  yours; the checkout is shared with other agents.

**Amber — allowed, but it costs something, so it goes in the change's own words.**

- Real-model runs: `npm run test:llm`, `npm run llm:quality`, and any
  `generateStructured` call against a configured provider. These spend money and
  are deliberately on-demand rather than in `check:ci`. Say in the commit
  message what you proved and against which model.
- Accepting a golden (`npm run llm:eval:update -- --reason "…"`), accepting a
  regenerated instruction block (`npm run agents:surface -- --accept "…"`),
  adding a `.github/security/sast-allowlist.json` entry **and raising its ceiling
  in `.github/contract-ledger.json`, which is now the only way the entry passes
  `check:ci`**, raising any ratchet baseline. Each is legitimate sometimes and each is what an agent under time
  pressure reaches for — the rubric's B3 exists to ask, every time, whether the
  finding was fixed or absorbed. Never raise a ratchet you could have lowered.
- Adding a runtime dependency or deleting a test: allowed, with an `Ack:` line
  saying why (ADR-0008). The review blocks without one.

**Red — stop and ask, and do not decide on the operator's behalf.**

- **Anything that spends an advertiser's budget or mutates a real ad account.**
  `SKLIK_WRITES_ENABLED` arms real Sklik mutations and is off unless the exact
  value is `1`; the live proof for that path is the owner's and its steps are in
  `docs/deploy.md` § Sklik writes. Never set it, never widen the guard, never
  add a second one modelled on it, and never run the write path against a real
  token to "check".
- **Anything that leaves the machine under the operator's name**: publishing a
  post, sending mail through Resend, uploading conversions to Google Ads,
  contacting a person. Drafts go through the review gate in `schranka`; the
  operator presses send.
- `git push`, and especially any push to `master` — Vercel ships master on push,
  so the push *is* the release. `SYSTEDO_SKIP_GATE=1` is the operator's escape
  hatch, not yours.
- Editing `.env*`, printing a secret, or moving a credential anywhere — including
  into a test fixture, a log line, or a prompt.
- Touching a CODEOWNERS law file (billing, metering, the LLM chokepoint, the
  agent instruction surface, `.github/workflows/`, security policy, the ADRs)
  beyond what the task explicitly asked for.
- Loosening a gate to make your own change pass. Fix the finding, or bring the
  operator the reason it should not be a finding.

Two of these are enforced rather than trusted, which is the point: `npm run sast`
blocks a route with no caller identity and a client module reading a server env
var, and `npm run actions:check` blocks a workflow that would splice an
expression into a shell. The rest are load-bearing on you.

**And the list itself is now a boundary, not only a paragraph.** Every rule around
this section grew a fence — the seams are lint rules, the security rules are `npm
run sast`, the token scopes are `.github/workflow-permissions.json` — while the one
about what may run WITHOUT ASKING stayed prose, in a tree holding live Google Ads,
Sklik, Resend, Leonardo and provider credentials.
[`.github/agent-permissions.json`](.github/agent-permissions.json) states the same
three rungs as patterns a harness can match: `deny` for the things above that say
*never*, `ask` for the two that spend money or absorb a finding, `allow` for the
offline gates — each carrying the sentence above that it comes from and, the half a
permission list never carries, what the pattern **cannot** see (a shell, an intent,
a harness that is not this one). `npm run agent:permissions -- --install` writes it
into `.claude/settings.json`, which is where a denied command is refused rather than
remembered; `npm run agent:permissions:check` says whether your checkout is wired.
The prose stays canonical and the drift is what is measured:
`test-unit/agent-permissions.test.mjs` blocks when a rule's quote is no longer a
sentence here, when a rung sits on the wrong list, or when the settings file
enforces a pattern the declaration does not — so the two cannot become two
different answers to "may I run this?".

## AI registry (knowledge + skills)

This repo is wired to the organization's AI registry - ONE local checkout, at the path in
`.ai/manifest.yaml` under `registry.local` (default `../ai-registry`).

- **The knowledge is already loaded.** `.claude/rules/ai-registry-*.md` are installed copies
  of the registry's generated rules - the access contract plus a subject map per domain in
  `knowledge.domains`. Before a design, architecture or product decision in a covered
  domain, open the governing subject through `knowledge/<domain>/index.json`
  (`subjects["<slug>"].file`), never by building a path from a slug. `/consult <topic>`
  does the same read deliberately and logs it.
- **Shared skills are links, not copies.** Every name in `.ai/manifest.yaml` `skills:` is
  linked from `.claude/skills/<name>` into the registry's lane; editing one edits the
  registry's file. A real directory under `.claude/skills/` is project-owned. After changing
  the manifest, run `node <registry>/scripts/link-registry.mjs` (`--check` verifies).
