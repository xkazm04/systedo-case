## Per-lens findings (new sites)

### Lens 1 — code quality (plumbing)
Uniformly **strong (code_score 5)**. Every new site is a proper chokepoint call with native schema + normalize + a `validate`/self-repair gate + a deterministic keyless demo, inheriting the wrapper's telemetry/fallback/corrupt-detection. Specific wins:
- **[[twin-reply]]** closes both of [[lead-reply]]'s open items — added route **caching** (`cachedRespond`, route.ts:482) and kept the **validate gate** (empty-reply / missing-confidence / non-array-risks → self-repair).
- **[[monthly-recap]]** has the best caching design in the set: two layers — in-memory `cachedRespond` keyed on an *effective-grounding-versioned* `keyId` (edits/re-syncs/staleness re-key correctly, no cross-tenant bleed) **plus** durable per-month persistence (`recordRecap` + `recapInputHash`) so the report page never regenerates on visit.
- **[[twin-style]]** is a hardened **meta call** — two-layer do/dont constraint validation (normalize coerces non-"don" → "do" so a guardrail never silently inverts; gate rejects <40-char directives so a blank voice can't overwrite a trained one).
- **[[onboarding-scan]]** is **auth-gated + SSRF-guarded** on the server-side site fetch — anonymous callers can't use it as a fetch proxy.

Nits (all low/cosmetic): registry `system`-string paraphrases drift from source prompts (protected by golden promptHash) on channel-research/local-diagnosis; onboarding-scan digests text to 6000 but fetches 8000 (last ~2000 chars unseen); chat re-sends full transcript uncached each turn (bounded by 24-turn/2000-char caps); duplicate `TwinChannel` label map in twin-reply + twin-style.
